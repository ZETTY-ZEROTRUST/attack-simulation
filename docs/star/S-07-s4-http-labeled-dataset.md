# S-07 정상·S4-A HTTP 정답 데이터셋

- 상태: 파일럿·확대 캡처 완료
- 날짜: 2026-10-03
- 코드: [데이터 생성기](../../datasets/s4_http/README.md)

## S — 문제

GitHub access2.log에는 공격 정답이 없어 정밀도·재현율을 평가할 수 없다. 알려진 정상·S4-A 행동을 실제 로컬 서비스에 흘리고, 학습 입력과 분리된 정답이 필요하다.

## T — 목표

정상-only 학습·보정과 독립 95:5 테스트를 실제 사용자별 60초 구간으로 만든다. 정상 피크도 포함하고, 토큰·본문·개인정보를 저장하지 않는다. 인증·인가 통과와 행동 탐지를 구분한다.

## A — 구현과 검증

- TLS CA 검증, loopback 대상 고정, proxy·redirect 차단.
- 요청량·시간·concurrency·응답 크기·timeout 상한, 900초 토큰 수명 안의 split별 새 로그인.
- 정상 느린 조회·고활동·피크와 S4 반복·burst·조회 범위 확대.
- 응답 크기 출처는 client_observed_body_bytes, 본문 저장 없음.
- request_id로 API ACCESS_DECISION의 actor.subject_key만 조회해 연결 검증.
- label/profile/split/cohort/ID/절대 시각은 피처와 분리.
- 오류·거부·누락·중복·매핑 불일치는 품질 실패. 정상으로 대체하거나 삭제하지 않음.
- 첫 파일럿 시작 후 향후 실행 코드에 source SHA256·런타임 버전 기록을 추가했다. 첫 실행의 시작 시점 소스 해시는 없어 완전한 소스 재현성이 검증됐다고 주장하지 않는다.

## 확대 캡처 실측 완료

기존 모의 계정100개 로그인100/100 성공 후 다음 명령을 실제 실행했다.

```bash
python3 datasets/s4_http/runner.py --actors 100 --train-windows 2 \
  --calibration-windows 2 --test-windows 10 --max-requests 65000 \
  --max-seconds 1100 --seed 20261004
```

profile_version=2-overlapping-normal-peaks는 정상 burst60~120회/분으로 공격100~140회와 중첩시킨 사전 생성 분포다. 첫 파일럿과 다른 분포이므로 두 자료의 성능 차이를 모델 개선 효과로 해석하지 않는다. 같은 자료 안에서 사전 고정된 모델들을 비교한다. 새 capture의 source SHA256와 파일 hash를 저장했고 종료 시점 코드 hash가 시작 snapshot과 일치함을 확인했다. 모든 split은 실제 시간상 겹치지 않는다.

시간936.09초는 최초 계정 로그인 뒤 첫 capture 시작부터 split 사이 로그인·최종 검증까지다. 14개의 실제60초 창이 있으며 나머지는 로그인·저장·연결 검증 시간이다. 로컬 client latency는 운영 성능·최대 처리량 지표가 아니다. 초기 파일럿과 확대 결과 파일은 불변 보존했고 모델 학습 담당에게 완료·품질 통과를 전달했다.

## 해석 한계

통제된 유효 모의 토큰 사용의 행동 이상 실험으로 실제 탈취 성공·쿠팡 사고 재현·운영 침해율을 입증하지 않는다. 평가 단위는 요청이 아닌 사용자×시간 창이다. 파일럿 공격5개와 보정 정상40개로 성능·1% 오탐 임계값을 안정적으로 추정할 수 없다. 95:5와99:1은 실험 비율이며 실제 사고 비율 근거가 아니다.

## 자소서에 쓸 수 있는 검증 사실

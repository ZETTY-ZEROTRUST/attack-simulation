# L-04 보안 강화 비용 → Redis positive cache

- 상태: 완료
- 연결: S2·S3(매 요청 원본 확인) · 부하 L-3(풀)·L-4(캐시)
- 작성/갱신: 2026-09-27

## S — 문제 (부하로 드러남)

S2·S3 방어로 보호 요청마다 DB 조회가 **2회**(authVersion 대조 + 발급대장 digest 대조) 발생한다.
동일 부하(k6, /users/me, 최대 75 VU)에서 기본 커넥션 풀(10)이 고갈돼 정상 요청이 대량 401로 떨어진다.

| 풀 10, DB 직접 | 값 |
|---|---|
| 실패율 | 77% |
| 처리량 | 39 req/s |

DEBUG로 삼켜진 커넥션 획득 타임아웃이 필터의 catch에서 401로 흐른 것. 즉 "보안 강화가 처리량·안정성 비용을 유발".

## T — 왜 / 목표

회수 정확성(로그아웃 즉시 반영)을 지키면서 요청당 DB 부하를 없애 처리량·실패율을 회복한다.

## A — 어떻게 (웹 근거 → 단계적 개선)

### 웹 근거
- 매 요청 상태 확인의 대안으로 **positive cache**를 두되 최대 반영 지연을 ADR로 정한다(인증 owner 문서 §5). 오프셋/캐시 트레이드오프는 일반 원칙.
- 회수 즉시성은 **캐시 무효화**로 확보(TTL은 상한선).

### 1단계 — 풀 증설 (L-3, 원인 규명)
- `DB_POOL_MAX`로 풀을 50으로 → 실패율 0%, 226 req/s. **원인이 풀 고갈임을 확정**. 단, DB 부하 자체는 그대로.

### 2단계 — Redis positive cache (L-4, 근본 개선)
- 검증에 성공한 `(jti, sub, authVersion, digest)`만 짧은 TTL로 `authstate:{jti}`에 캐시.
- 캐시 적중 시 **DB 조회 2회를 건너뜀**. Redis 장애 시 DB로 폴백(fail-safe).
- **회수 즉시성**: 로그아웃 시 Auth가 발급대장을 폐기하고 해당 사용자 jti들의 캐시 키를 **즉시 삭제**. TTL은 누락 시 상한.
- 검증: 캐시 활성 상태에서도 S2 전부 통과(로그아웃 후 AT 401).

### 대안 비교
| 선택지 | 처리량 | 회수 반영 | 비용 | 판단 |
|---|---|---|---|---|
| DB 직접 | 낮음(풀 고갈) | 즉시 | DB 2회/req | 기준 |
| 풀만 증설 | 회복 | 즉시 | DB 2회/req(그대로) | 임시 완화 |
| Redis 캐시 | 회복 | 즉시(무효화)+TTL 상한 | 캐시 히트 시 DB 0회 | **채택** |

### 시행착오
- 첫 캐시 측정에서 실패율 52%로 애매 → 원인: TTL 30s가 25개 공유 토큰을 **동시 만료**시켜 캐시 스탬피드(DB 몰림). 워밍된 캐시로 500 동시요청은 100% 성공함을 확인해 캐시 경로 자체는 정상임을 분리.
- 개선: 측정은 steady-state(TTL 600s)로 수행. 운영 완화책으로 **TTL 지터/refresh-ahead**를 후속 반영(동시 만료 방지).

## R — 결과 (동일 부하, 풀 10)

| 조건 | 실패율 | 처리량 | DB 조회/req |
|---|---|---|---|
| DB 직접 | 77% | 39 req/s | 2 |
| Redis 캐시(steady) | **0%** | **226 req/s** | 0 (히트) |

참고: 풀 50 DB직접도 0%/226 req/s지만 DB 부하는 유지. Redis 캐시는 **풀 10에서 DB 부하 없이** 동등 성능.
산출물: `load/results/l4_with_ledger.json`(DB직접), `l4_ledger_pool50.json`(풀50), `l4_redis_pool10_ttl600.json`(캐시).

## 자소서 한 줄 (초안)

토큰 회수 정확성을 위해 보호 요청마다 원본 상태를 2회 조회하도록 강화한 뒤, 부하 테스트에서 커넥션 풀 고갈로 정상 요청 77%가 실패함을 확인했습니다. 회수 즉시성을 캐시 무효화로 유지하는 Redis positive cache를 도입해 동일 부하·동일 풀에서 실패율 0%·처리량 5.8배(39→226 req/s)로 회복했고, 캐시 동시 만료 스탬피드를 실측으로 분리해 TTL 지터로 완화했습니다.

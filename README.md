# ZETTY 인증·인가 이상행동 탐지 시나리오

2026-11-22 확정한 Jev 평가 시나리오 4종이다. 로컬 모의 계정과 합성 업무 데이터를 전제로 하며, 현재 단계는 평가 설계다. 인증·인가와 발급대장 검증은 서버가 집행하고, Jev는 서버가 관측한 사건을 추가로 조사할지 판단한다. OWASP 매핑은 ZETTY의 설계 기준이다. [OWASP Web Top 10:2025](https://top10.owasp.org/2025/)

## ① 고객 계정 탈취 의심 세션

- **실제 사례** — GS리테일에서 공격자가 크리덴셜 스터핑으로 로그인에 성공한 뒤 회원정보 수정 페이지에서 개인정보를 열람했다. [개인정보위 조사 결과](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=C020010000&nttId=12425)
- **OWASP** — A07:2025 Authentication Failures. 다른 곳에서 유출된 자격 증명으로 계정에 접근하는 위험에 해당한다.
- **Jev 탐지 기준** — 민감정보를 조회한 시점에 새 로그인 이후의 업무 순서와 해당 계정의 이전 조회 이력을 비교한다. 평소 이용 흐름과 다른 민감정보 열람이 이어지고 이를 설명할 근거가 부족하면 추가 본인확인 검토 대상으로 표시한다. 현재 로그인 실패 이벤트에는 검증된 계정이 없고 토큰 갱신 시 세션 상관 키가 달라지므로 첫 평가는 로그인 성공부터 첫 갱신 전까지로 한정한다.
- **정상 대조군** — 고객이 새 기기에서 비밀번호를 잘못 입력한 뒤 로그인해 최근 주문과 배송지를 확인한다. 동일한 민감 경로를 방문하는 사례를 양쪽에 포함한다. 관측된 행동과 과거 이력까지 같으면 판단을 유보한다.

## ② 타인 주문에 대한 반복 접근

- **실제 사례** — 개인정보위는 써브웨이·한국파파존스에서 다른 고객의 주문정보가 노출될 수 있어 조사에 착수했다. 별도로 전북대 사건에서는 다수의 타인 개인정보에 반복 접근한 사실을 조사 결과로 발표했다. ZETTY는 주문별 소유권 검사가 작동하는 상태에서 반복 시도를 평가한다. [주문정보 사건 조사 착수](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=C020010000&nttId=11320) · [전북대 조사 결과](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=&nttId=11273)
- **OWASP** — A01:2025 Broken Access Control. API 단위에서는 주문 한 건마다 소유권을 확인하는 문제에 해당한다. [API1:2023 Broken Object Level Authorization](https://owasp.org/API-Security/editions/2023/en/0xa1-broken-object-level-authorization/)
- **Jev 탐지 기준** — 같은 세션에서 거부된 고유 주문 수, 동일 주문 재시도 비율, 본인 주문 조회 전후 흐름을 함께 본다. 거부 이후에도 대상이 계속 바뀌는 흐름을 조사 후보로 삼는다. 현재 API는 주문 부재와 소유권 불일치를 같은 사유로 기록한다. 실제 타인 소유 여부는 합성 데이터의 평가 정답에만 둔다.
- **정상 대조군** — 공유 브라우저에서 계정을 전환한 고객이 이전 계정의 주문 탭 여러 개를 다시 연 뒤 자기 주문 목록으로 돌아간다. 거부 횟수가 같은 사례끼리 비교한다.

## ③ 직원 권한 내 업무 무관 고객정보 수집

- **실제 사례** — 신한카드 영업점이 가맹점주 정보를 카드 모집 영업에 제공했다는 공익신고 후 개인정보위가 유출 정황을 확인해 조사에 착수했다. 아래의 직원 조회 속도·배정·승인 이력은 ZETTY에서 설계한 모의 조건이다. [개인정보위 발표](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&nttId=11710)
- **OWASP** — A09:2025 Security Logging and Alerting Failures. 허용된 조회가 누적되는 동안 업무와 맞지 않는 행동을 기록·경보하지 못하는 **방어 측 실패**에 대응한다. [OWASP A09](https://top10.owasp.org/2025/A09_2025-Security_Logging_and_Alerting_Failures/)
- **Jev 탐지 기준** — 팀 권한 내의 성공한 조회를 대상으로, 고유 고객 수와 신규 대상 비율을 당시 상담 배정·대체근무·일괄작업 승인 내역과 비교한다. 업무로 설명되지 않는 대상 확장이 단시간에 집중되거나 여러 날 누적되는 사례를 평가한다. 현재 백엔드에 직원·팀·배정 모델을 추가하고 시점별 업무 기록을 연결해야 한다.
- **정상 대조군** — 승인된 월말 정산으로 단시간에 많은 고객을 조회한 직원, 대체근무 중 여러 날 같은 규모의 상담을 나눠 처리한 직원. 조회 건수와 고유 고객 수를 맞추고 업무 맥락이 판정에 주는 차이를 측정한다. 배정 이력 누락은 미배정의 증거로 쓰지 않는다.

## ④ 쿠팡 사례 기반 미발급 토큰 반복 사용

- **실제 사례** — 쿠팡 민관합동조사단은 위·변조된 전자 출입증으로 타인 계정에 접근한 사실을 확인했고, 개인정보위는 인증 서명키 관리 소홀을 지적했다. ZETTY에서는 이 위험을 발급대장에 없는 자격의 반복 사용으로 모델링한다. [민관합동조사 결과](https://www.korea.kr/briefing/policyBriefingView.do?newsId=156744092) · [개인정보위 제재](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=D010030000&nttId=12171)
- **OWASP** — A04:2025 Cryptographic Failures. 이 매핑은 사고의 서명키 노출·관리 위험에 해당한다. [OWASP A04](https://top10.owasp.org/2025/A04_2025-Cryptographic_Failures/)
- **Jev 탐지 기준** — 서버가 서명을 검증하고 발급대장에서 미발급으로 확인해 거부한 사건을 시간 구간·보호 경로별로 집계한다. 분산된 단발 사건인지, 여러 경로에서 반복되어 함께 조사할 사건인지 판정한다. 집계 단위는 사건이며, 인증에 실패한 요청의 토큰 내용으로 사용자나 동일 공격자를 특정하지 않는다.
- **정상 대조군** — 정상 키 교체 전후에 정당하게 발급된 토큰으로 같은 경로를 이용하는 흐름. 별도 장애 대조군에는 발급대장 조회 불가로 거부가 집중된 구간을 둔다. 대장을 읽지 못한 사건과 실제로 대조해 미발급이 확인된 사건은 구분한다.

## 공통 평가 기준

- 코드는 판단 시점 이전의 이벤트만 집계한다. Jev에는 허용된 행동 요약과 당시 업무 맥락을 전달한다. 토큰·쿠키·고객정보 원문, 시나리오 ID, 사후 조사 정답은 입력에서 제외한다.
- 판정은 **검토 필요 / 정상 흐름과 일치 / 근거 부족**으로 기록한다. 필수 이벤트 누락과 호출 실패는 별도의 미평가 건수로 집계한다.
- 질문과 판정 임계값을 고정한 뒤 독립 사례에서 단순 규칙과 비교한다. ①~③은 정상 계정당 경보 수, ④는 정상 운영 시간당 경보 수를 맞추고, 사건별 재현율·첫 경보까지의 시간·미평가율을 보고한다. 초기 평가는 관찰 모드로 수행한다.

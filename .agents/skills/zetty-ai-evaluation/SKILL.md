# Jev 행동 평가·보고서와 독립 평가

현재 세션의 최신 사용자 지시를 우선하고 attack-simulation/README.md, log-pipeline/contracts/README.md와 관련 실제 코드를 읽는다. 삭제된 루트 문서나 이전 HTTP 실험 디렉터리를 복원하지 않는다. 경로는 루트 기준이다.

## 현재 사용자 방향

직접 가중치 학습·재학습·튜닝은 종료했다. IF·One-Class SVM·K-Means의 코드·모델과 과거 보고서·캡처 데이터는 사용자 요청으로 삭제했다. 이를 복원하거나 신규 fallback으로 쓰지 않는다. 현재 사용자는 log-pipeline이 가공한 입력을 uba-analyzer의 Jev가 평가하고 보고서를 작성해 Slack에 알리는 구조를 지정했다. Jev는 설계 대상이며 실제 API 지원·탐지 품질·전송 검증 완료를 뜻하지 않는다. 다른 제공자나 별도 설명 LLM을 임의로 도입하지 않는다.

## Jev 입력·보고서를 평가할 조건

- 먼저 공격/정상 시나리오와 관측 가능성을 고정한다. 같은 입력에서 구별 불가능한 의도는 모델 성능 문제로 숨기지 않는다.
- Jev의 실제 API·구조화 출력·입력 한계·버전 고정·가격·지연·데이터 취급을 공식 문서로 확인한다. 구조화 출력과 탐지 정확도, 제공자 confidence와 실측 정답률을 구분한다.
- 숫자 집계·시간 비교·명시적 권한 판정은 코드가 수행한다. AI에 남기는 맥락 판단이 무엇인지 설명한다. 임의 factor 가중치 합산·공격자 등급을 새 계약으로 넣지 않는다.
- 서버에서 확인한 행동 집계·업무 맥락·판단 시점 이전 이력을 허용 필드로 직렬화한다. 원문 개인정보·인증정보·자유 입력의 지시문을 신뢰 데이터로 넣지 않는다.
- 사례 정답·공격/정상 역할 라벨·시나리오명·미래 이력과 입력을 분리한다. 당시 서버가 확인한 직원 역할·배정·승인은 허용된 업무 맥락으로 구분한다. 계정·세션·겹치는 창·capture의 누수와 반복 표본 부풀리기를 검사한다.
- 질문/criteria·입력 변환·threshold를 개발 자료에서 고정한 후 새 holdout으로 평가한다. 삭제된 과거 학습·평가 자료를 복원해 새 최종 평가로 사용하지 않는다.
- 같은 관측과 비교 가능한 결정 과제로 단순 규칙 기준선과 Jev를 비교한다. 제공자별 편법 입력이나 정답을 노출하는 설명을 추가하지 않는다.

## 결과·집행·실패

탐지 → 정책 → Auth/BFF 집행을 분리한다. 초기에는 관찰/DRY_RUN, 실제 조치는 승인된 local 모의 계정 범위다. AI 호출을 매 API 요청의 인가 선행 조건으로 만들지 않는다.

timeout·429·형식/모델 불일치·입력 누락은 미평가이며 정상 점수로 채우지 않는다. 정보 부족에 의한 판단 유보와 API 장애도 구분한다. 재시도·총 기한·backlog·중복 호출/명령을 제한한다. 공통 schema의 실제 enum을 확인하고 필요하면 revision/fixture/consumer를 함께 바꾼다.

TP/FP/FN/TN·정상 계정당 경보·미평가율·평가 coverage·지연·실제 비용을 표본과 함께 보고한다. 낮은 비용/빠른 응답만으로 채택하지 않는다. mock은 계약 검증일 뿐 실측 탐지 성능이 아니다. 공개 dataset 성과와 local API 성과를 구분하고, 유료 호출/외부 전송은 요청된 범위를 따른다.

## 구조 설계 참조

[시나리오 기반 구조 설계](../../references/system-design.md)를 입력 집계, 세 가지 판정과 별도 미평가 상태, 보고서 근거 검증, Slack 재시도 경계를 설계할 때 읽는다. 초기에는 관찰 모드이며 실제 발송은 별도 실행 범위다.

판정은 검토 필요 / 정상 흐름과 일치 / 근거 부족이다. 필수 입력 누락·호출/출력 실패는 별도 미평가 상태로 남긴다. Jev 보고서의 근거 참조·비밀값·길이·형식을 검증하고, 사실 일치도는 독립 평가로 확인한다. 보고서 확정과 알림 작업을 함께 영속화하며 Slack 재시도 때문에 Jev를 재호출하지 않는다.
